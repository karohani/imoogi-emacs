00

조사에서 알게 된 것

먼저 쉬운 말로: Anki에는 "노트 타입"이라는 카드 틀이 있고, 그중 Cloze(빈칸 채우기) 틀은 문장 안의 {{c1::정답}} 표시를 빈칸으로 바꿔 보여줍니다. logseq 플러그인은 겉보기엔 카드 유형이 여러 개지만, 실제로는 모든 유형을 이 Cloze 틀 하나로 변환합니다. 우리 프로젝트에는 이미 imoogi-Cloze 틀이 있으니, 바꿔야 하는 건 "본문을 어떻게 Cloze 문장으로 조립하느냐"뿐입니다.

  • 요청하신 문서 URL(…/docs/card-types)은 404였습니다. 대신 GitHub 위키(클론)와 src/notes/*.ts 소스를 읽었습니다.
  • 현재 imoogi-anki는 ANKI_NOTE_TYPE이 붙은 헤딩 1개 = 노트 1개이고, 본문은 다음 헤딩 직전까지만 읽습니다(하위 헤딩 제외). orgdoc.Render를 부르는 곳은 planner.go와 migrate.go 두 군데입니다.
  • go-org 렌더를 직접 돌려본 결과(실측): #+BEGIN_CLOZE는 <div class="cloze-block">, 목록은 <ul><li>, {{c1::bar}}는 그대로 통과, :-> 화살표는 :-&gt;로 이스케이프됩니다.
  • "가상 노트 타입명" 꼼수(예: imoogi-Multiline)는 planner와 registry가 실제 Anki 모델명을 가정하고 있어 쓸 수 없습니다.
Cloze (빈칸 카드)
문장 일부를 가리고 맞히는 카드. Anki는 {{c1::…}} 표시 하나당 카드 1장을 만들고, 같은 번호는 같은 카드에서 함께 가려집니다.
프로토콜 (protocol)
Emacs와 Go 바이너리가 주고받는 JSON 문서의 약속. 필드가 늘면 버전 번호를 올려 구버전 바이너리를 걸러냅니다.
registry
어떤 헤딩이 Anki의 어떤 노트 ID와 짝인지 기록한 로컬 장부. 헤딩 1개당 1건입니다.
drawer
Org 헤딩 바로 아래 :PROPERTIES: … :END: 사이의 속성 목록. ANKI_NOTE_TYPE 같은 값이 여기 들어갑니다.
01

확정된 원칙

대화에서 합의한 다섯 가지입니다. 아래 모든 카드가 이 원칙 위에 서 있어요.

  1. 새 Anki 노트 타입 없음. 모든 카드 유형은 기존 imoogi-Cloze로 만듭니다.
  2. Cloze 표기는 편집기 명령이 만듭니다. Go가 {{cloze X}} 같은 대체 문법을 해석하지 않아요. 영역을 잡고 imoogi-anki-cloze를 부르면 {{cN::…}}가 됩니다.
  3. 노트 타입은 편집 시점에 drawer에 기록됩니다. cloze 명령이나 방향 지정 명령이 ANKI_NOTE_TYPE이 없으면 imoogi-Cloze를 써 줍니다. 동기화 때 Go는 타입을 바꾸지 않고 검증만 합니다.
  4. 카드 옵션 속성은 세 개. ANKI_DIRECTION(->|<-|<->), ANKI_INCREMENTAL(t), ANKI_SWIFT(t). 방향이나 incremental이 있으면 Multiline(Q/A) 카드, ANKI_SWIFT가 있으면 Swift 카드입니다. 별도 ANKI_CARD_KIND는 두지 않아요.
  5. 세 속성 모두 상속됩니다. ANKI_DECK처럼 가까운 값이 이기고, #+PROPERTY:로 파일 전체에 지정할 수 있어요. 다만 "이 헤딩이 카드인가"는 여전히 자기 drawer의 ANKI_NOTE_TYPE이 정합니다.

질문/답 카드는 이미 imoogi-Basic(앞면=제목, 뒷면=본문)으로 만들 수 있지 않나요? 맞습니다. Multiline이 새로 보태는 건 역방향·양방향(<-, <->)과 incremental(답 항목마다 카드 한 장씩)입니다. 단순 정방향 Q/A는 지금처럼 Basic을 쓰면 됩니다.

실제 예시로 보면 이렇습니다. 사용자가 Anki 메뉴에서 방향 <->를 고르면 왼쪽처럼 속성 두 줄이 drawer에 기록되고(노트 타입은 명령이 채워 줌), Go가 오른쪽처럼 Cloze 문장을 조립해 Anki에 보냅니다. 답(c1)과 질문(c2)이 각각 가려지는 카드 2장이 생깁니다.

Org (명령이 기록한 결과)

* 일본의 수도는?
:PROPERTIES:
:ANKI_NOTE_TYPE: imoogi-Cloze
:ANKI_DIRECTION: <->
:END:
- 도쿄
#+BEGIN_EXTRA
일본 최대 도시. 인구 약 1,400만.
#+END_EXTRA

Anki 필드 (Go가 만드는 것)

Text:
{{c2::<p>일본의 수도는?</p>}}
<ul class="children-list">
  <li>{{c1::도쿄}}</li>
</ul>

Back Extra:
<p>일본 최대 도시. 인구 약 1,400만.</p>

빈칸 카드 하나만 만들 때는 더 간단해요. 본문에서 도쿄를 드래그하고 imoogi-anki-cloze를 부르면 {{c1::도쿄}}로 바뀌고, 헤딩에 ANKI_NOTE_TYPE이 없으면 imoogi-Cloze가 같이 기록됩니다. 같은 헤딩에서 한 번 더 부르면 c2, 같은 카드로 묶고 싶으면 C-u 1을 앞에 붙이면 됩니다.

작업 분할 — 백로그 카드

moai todo에 등록한 순서입니다. t11과 t12는 서로 독립이고 프로토콜을 건드리지 않아 단독 배포할 수 있어요. t13이 t14·t15의 토대입니다.

t11 · Elisp만

cloze 편집 명령 imoogi-anki-cloze

영역을 {{cN::…}}로 감싸는 명령. Go와 프로토콜은 손대지 않습니다.

  • N은 현재 헤딩 본문의 최대 cloze 번호 + 1, C-u N으로 직접 지정, 영역이 없으면 커서 단어
  • 영역 안 }}는 } }로 띄우고, 선택이 }로 끝나면 {{cN::… }}처럼 닫기 앞에 공백을 넣음 — Anki의 cloze 정규식은 첫 }}에서 닫히기 때문 (LaTeX에는 무해)
  • ANKI_NOTE_TYPE이 없으면 imoogi-Cloze 기록, 다른 값이면 바꾸지 않고 알림
  • Anki transient(C-c a)에 바인딩. 되돌리기 imoogi-anki-uncloze는 선택
modules/org/anki/imoogi-cloze.el (신규)imoogi.el (transient)선행 없음

Multiline(Q/A) 카드

t15 · Swift

Swift 화살표 카드

ANKI_SWIFT: t 헤딩의 본문에서 설명 :-> 내용 같은 줄을 찾아 화살표 방향대로 가립니다. 렌더 전 텍스트 단계에서 처리합니다(렌더 후에는 >가 이스케이프됨).

  • 줄 단위 정규식 (.+?)\s*(:<->|:->|:<-)\s*(.+). i번째 줄은 오른쪽 c(2i−1), 왼쪽 c(2i) — :->는 오른쪽만, :<-는 왼쪽만, :<->는 둘 다(카드 2장)
  • 화살표는 <b>로 강조, 제목은 문맥으로 상단. 헤딩당 노트 1개(카드 N장)

t12 — 죽어 있던 Back Extra 필드를 살림

Back Extra 필드는 노트 타입에 선언돼 있고(model.go:99) 카드 뒷면 템플릿도 그 필드를 렌더하는데(assets/cloze-back.html:4), 채우는 코드가 없어 지금까지 영구히 비어 있었어요. t12는 신규 기능이자 이 죽은 필드를 되살리는 작업이었습니다. Render 시그니처를 바꾸지 않아 프로토콜·planner·registry는 그대로예요.

  • internal/anki/orgdoc/extra.go 신규 — splitExtraBlocks가 본문에서 #+BEGIN_EXTRA … #+END_EXTRA를 떼어냅니다. 대소문자 무시(Org 키워드 규칙), 줄 시작 고정, 여러 블록은 빈 줄로 이어 붙임
  • 블록이 없는 본문은 바이트 그대로 반환 — 트림조차 하지 않습니다. planner가 렌더 결과를 해시하므로 여기서 정규화하면 기존 카드 전부가 내용 변화 없이 updated로 뜹니다
  • 마커 검사는 EXTRA를 뺀 나머지에만 겁니다 — Anki의 cloze 템플릿은 {{cloze:Text}}만 읽으므로, 마커가 EXTRA 안에만 있으면 빈칸 없는 노트가 되어 Anki가 거부합니다
  • Back Extra는 비어 있어도 항상 내보냅니다 — AnkiConnect는 주지 않은 필드를 그대로 두기 때문에, 키를 생략하면 EXTRA를 지운 카드의 예전 내용이 컬렉션에 영원히 남습니다
  • imoogi-Basic은 그대로 — Basic에는 그 필드가 없어 키를 내보내면 note_field_missing이 납니다. EXTRA는 지금처럼 Back 안에 인라인으로 남습니다

t12 — 경계에서 잡은 회귀 하나

Back Extra를 내보내기 시작하자 스톡 Cloze 노트 타입이 깨졌습니다. imoogi-Cloze의 필드는 Text/Back Extra인데 스톡 Cloze는 Text/Extra이고, 필드 해석이 이름을 정확히 맞춰 찾기 때문에 손으로 쓴 스톡 Cloze heading이 note_field_missing으로 실패했어요. 이 프로젝트는 스톡 타입 동기화를 명시적으로 지원하므로 회귀입니다. Go 전체 테스트는 통과하고 있었는데, 스톡 Cloze를 add 경로로 통과시키는 테스트가 없었기 때문이에요.

  • 재현 테스트를 먼저 써서 실패를 확인한 뒤 고쳤습니다 (internal/anki/planner/extra_alias_test.go, 2개)
  • clozeExtraAliases 추가: back extra ↔ extra. 정확한 이름 매칭이 실패한 뒤에만 참조하고, 두 이름 다 없는 모델은 여전히 note_field_missing으로 실패합니다
  • 제 변경으로 거짓이 된 fake_client_test.go의 주석도 함께 고쳤습니다
