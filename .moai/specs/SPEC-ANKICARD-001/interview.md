## 열린 질문 (리서치/SPEC 에서 답할 것)
- `{{Deck}}` 특수 필드의 정확한 값 형식(`::` 중첩 덱이 클래스명에 들어갈 때의 이스케이프) — 클래스명 정규화 규칙 필요
- 미디어가 콘텐츠 해시(`hashing.Hash`)에 어떻게 들어가는가 — 이미지 내용이 바뀌면 업데이트가 나가야 하는가(해시에 파일 해시 포함 여부)
- 레지스트리가 업로드한 미디어를 추적해야 하는가(고아 미디어 정리 범위 — 이번 SPEC 제외 후보)

- `createModel` 이 이미 존재하는 타입을 만나면? (idempotent 생성 + 스타일 갱신은 `updateModelStyling`/`updateModelTemplates`)
- "우아한" 의 구체 디자인 방향 — Phase 7 설계 방향 단계에서 정함 (라이트/다크·Anki 나이트모드 대응·타이포)

## 초안에 반드시 반영할 사항 (research.md 기준)
- REQ-016 을 "imoogi 가 만들지 않은 노트 타입" 으로 범위 개정, AC-016 을 소유권 범위로 대체, 원본 §4 "커스텀 노트 타입 제외" 를 이 SPEC 이 대체함을 선언 (§1)
- 변환(수식·이미지 src 재작성)은 해시 **앞**에서, 저장 텍스트는 해시한 것과 바이트 동일 — 고아 삭제 소유권 판정이 걸려 있음 (§6)
- 해시에 새 입력 추가 금지: 이미지 변경은 내용 해시 접미사 파일명으로 자동 반영 (§6)
- 첫 실행 시 기존 imoogi 노트 전체 1회 업데이트가 정상 동작임을 명시 (§6)
- `{{Deck}}` = `::` 포함 전체 경로 → CSS 클래스 정규화 규칙(소문자, `::`→구분자, `[a-z0-9_-]` 외 → `-`, 연속 축약, 숫자 시작 가드) — 래퍼는 카드 템플릿 쪽 (§3)
- 나이트 모드 `.card.nightMode` + `.card.night_mode`(공백 없이), `.card img{max-width:100%}`, `word-wrap:break-word` (§3)
- MathJax `\( \)` `\[ \]` 만, 수식 내 줄바꿈은 `<br>` (판정표)
- 미디어 고아 정리 범위 밖, 업로드 파일 `_` 접두 금지 (§7)
- 새 진단 코드는 Go const + Elisp 테이블 동시 추가 (계약 테스트가 강제)
