# 클립보드 멈춤 진단 로그 구현 계획

사용자 요청: 의심되는 멈춤이 다시 발생할 때 원인을 확인할 수 있도록 로그를 남긴다. 반복 읽기 최적화나 재진입 차단은 이번 변경에 포함하지 않는다.

## 설계

명시적으로 켜는 전역 `imoogi-clipboard-trace-mode`를 기존 클립보드 모듈에 추가한다. 기본값은 꺼짐이다. owner, 레지스트리 읽기, Org 미리보기 갱신, 클립보드 lease 갱신의 호출 시작·종료를 동일한 호출 ID로 연결하고 시각, 호출 깊이, 소요 시간, 성공/비정상 종료, 제한된 호출 함수명만 기록한다. 인자·반환값·노트 본문·파일 경로·에러 메시지 원문은 기록하지 않는다.

Emacs 사용자 디렉터리 아래 로컬 로그 파일에 즉시 추가한다. 크기 제한과 이전 파일 한 개만 유지한다. 기록 중 수정 훅과 재귀적인 기록을 억제하고, 기록 실패가 원래 함수의 반환값·오류·quit을 바꾸지 않게 한다. 로그는 마지막으로 진입한 함수 확인에 도움이 되지만 실제 UI 멈춤 원인이나 종료되지 않은 모든 호출을 보장하지 않는다.

메모리 전용 로그는 강제 종료 시 사라져 제외했다. 항상 켜는 상세 추적은 I/O 부하가 생겨 제외했다. 진단 모드와 로그 열기 명령, 재현 후 꺼야 하는 이유를 README에 안내한다.
