# 미리보기 책자·발표 보기 설계

- 작성일: 2026-11-11
- 상태: 구현 전 검토 초안 · 사용자 리뷰 검증 반영
- 대상: imoogi-emacs의 Org·Markdown 웹 미리보기
- 목표: 같은 문서를 스크롤로 읽거나, 책장을 넘기듯 읽거나, 한 페이지씩 발표한다.
- 범위: 화면과 동작 설계. 이 문서를 작성하면서 제품 코드는 변경하지 않는다.

## 1. 제안 요약

기존 미리보기에 **문서 / 책자 / 발표** 보기 전환을 추가한다.

| 보기 | 목적 | 기본 화면 | 내용 갱신 |
|---|---|---|---|
| 문서 | 편집하면서 확인 | 기존 세로 스크롤과 목차 | 기존 실시간 갱신 유지 |
| 책자 | 순서대로 집중해서 읽기 | 목차 + 한 쪽 또는 두 쪽 | 변경 알림 후 사용자가 적용 |
| 발표 | 다른 사람에게 설명 | 목차 없이 한 페이지, 전체 화면 선택 | 변경 알림 후 사용자가 적용 |

책자와 발표는 같은 원문을 사용한다. 내용을 자동 요약하거나 문장을 삭제하지 않는다.
보기 전환 시 페이지 번호보다 **읽던 원문의 위치**를 우선해서 복원한다.
PPTX 내보내기나 슬라이드 편집기는 이번 범위에 포함하지 않는다.

대상은 Emacs 버퍼의 실시간 미리보기와 링크로 연 저장된 Org·Markdown 문서다.
저장된 링크 미리보기에는 현재 실시간 변경 알림과 원문 버퍼 탐색이 없으므로,
같은 기능이 있다고 가정하지 않는다. 이 경우에는 `다시 불러오기`를 제공하고
원문 버퍼 이동 기능은 비활성화한다. 원래 버퍼 갱신으로 링크 전용 이미지 핸들이 소실되거나
generation이 바뀌는 경우는 §8에 따라 구분한다. 다시 불러오기도 허용되지 않으면 원래 문서에서 링크를 다시 열도록 안내한다.

## 2. 사용자 흐름

1. Emacs에서 기존 방식으로 미리보기를 연다.
2. 상단의 `책자`를 선택한다.
3. 문서의 제목 구조와 화면 크기를 기준으로 페이지를 만든다.
4. 목차 또는 이전·다음 버튼으로 읽는다.
5. `발표`를 선택하면 읽던 위치를 유지한 채 한 페이지 보기로 바뀐다.
6. 필요하면 `전체 화면`을 실행한다.
7. 원문 변경은 `새 내용 있음`으로 알리고 화면은 유지한다.
8. `최신 내용 적용`을 누르면 새 내용으로 페이지를 다시 구성한다.
9. `문서`로 돌아가면 최신 원문에서 대응하는 위치를 보여준다.

초안의 버튼 동작은 예시 문서로 구성한 모형이다. 실제 페이지 분할이나 Emacs 연동이 구현됐다는 뜻은 아니다.

## 3. 화면 구성

```text
┌──────────────────────────────────────────────────────────────┐
│ imoogi preview · 문서명                                       │
│ [문서] [책자] [발표]        [한 쪽 / 두 쪽] [최신 내용 적용]    │
├──────────────┬─────────────────────┬─────────────────────────┤
│ 목차         │                     │                         │
│ 1. 시작하기  │       왼쪽 페이지   │       오른쪽 페이지     │
│ 2. 작업 흐름 │                     │                         │
│ 3. 검토      │                     │                         │
│              │                 03  │                     04  │
├──────────────┴─────────────────────┴─────────────────────────┤
│ [← 이전]                    3–4 / 12쪽              [다음 →]  │
└──────────────────────────────────────────────────────────────┘
```

### 문서 보기

현재의 목차·개요·최근 문서·커서 추적을 유지한다. 새 기능을 사용하지 않는 사람의 동작은 바뀌지 않아야 한다.

### 책자 보기

- 넓은 화면에서는 두 쪽, 좁은 화면에서는 한 쪽을 표시한다.
- 목차·바깥 여백을 제외한 **본문 컨테이너의 실제 폭**이 `320px × 2 + 24px = 664px` 이상일 때만 양면 배치를 허용한다. 전체 창 너비를 이 기준과 직접 비교하지 않는다.
- 사용자가 한 쪽을 선택하면 화면이 넓어져도 한 쪽을 유지한다.
- 문서 시작에는 표지나 빈 페이지를 자동 삽입하지 않는다.
- 짝을 맞추기 위한 빈 페이지도 만들지 않는다. 마지막 페이지가 홀수이면 한 쪽만 표시한다.
- 원문의 제목을 목차로 사용하며 클릭하면 해당 제목이 있는 페이지로 이동한다.
- 글자 크기는 읽기 설정으로 제공한다. 변경하면 페이지를 다시 나누되 읽던 문단을 유지한다.

### 발표 보기

- 같은 내용을 한 페이지씩 표시한다. 목차와 편집용 강조는 숨긴다.
- 발표용 글자 크기와 여백을 사용하므로 책자 보기와 페이지 수가 달라도 된다.
- `전체 화면`은 사용자의 클릭으로만 요청한다. 브라우저가 거부해도 일반 창에서 발표할 수 있다.
- 사용자가 넘기지 않는 한 원문 수정이나 Emacs 커서 이동으로 페이지가 바뀌지 않는다.
- 자동 재생, 발표자 전용 창, 타이머, 페이지 전환 효과는 첫 구현에서 제외한다.

## 4. 페이지를 나누는 규칙

### 제목과 문서 구조

- 문서에 등장하는 가장 상위 제목 수준을 기본 장 구분으로 삼는다.
- 장 제목은 새 페이지에서 시작하고, 더 낮은 제목은 이어지는 본문으로 취급한다.
- 제목만 페이지 아래에 남지 않도록 제목과 바로 다음 블록을 가능하면 함께 배치한다. 큰 블록은 내부 스크롤로 처리하고 블록 안을 자르지 않는다.
- 제목이 없는 문서는 처음부터 본문 흐름에 따라 나눈다.
- YAML 메타데이터 표는 읽기 화면에서 `문서 정보`로 분리하고 기본 접힘 상태로 둔다.
- YAML 표는 렌더러가 부여한 `table.org-properties[data-org-format="yaml"]`로 식별한다. `white-space` 등의 스타일 문자열로 판별하지 않는다.
- Org 문서 중간의 속성 서랍에는 이 표시를 부여하지 않으며, 접지 않고 일반 본문 블록으로 유지한다.
- `name`·`description` 같은 임의의 메타데이터로 표지나 발표 내용을 자동 생성하지 않는다.
- 초기에는 기존 파서가 구분한 제목과 블록만 사용한다. 원문에 새 페이지 구분 문법을 추가하지 않는다.

### 첫 구현: 블록 단위 페이지 구성

첫 구현에서는 원문 블록의 내부를 잘게 나누지 않는다. 같은 DOM 요소를 페이지 사이로 이동시켜
이미지의 로드 상태와 기존 요소를 최대한 보존한다.

여기서 **이동할 블록은 페이지 래퍼를 만들기 전 `#root > main.org-preview`의 직계 자식 요소**다.
진입 시 `Array.from(main.children)`으로 원래 순서의 참조 목록을 한 번 확보한다.
하위 `li`·`span`에도 `data-org-id`가 있으므로 이 속성의 전체 검색 결과를 이동 단위로 사용하지 않는다.
목록 내부 항목과 인라인 요소는 부모 블록 안에 그대로 둔다.

### 페이지 래퍼의 위치와 복원

페이지 래퍼는 **기존 `main.org-preview` 안에** 생성한다. 이 설계에서는 래퍼마다
`org-preview` 클래스를 복제하는 대안은 사용하지 않는다.

```text
#root
└── main.org-preview
    ├── .reader-page                  ← 원래 직계 자식 블록을 이동
    ├── .reader-page                  ← 다른 쪽의 원래 블록
    └── .reader-measure               ← 측정할 때만 원래 블록을 잠시 이동
```

블록을 `main.org-preview`나 `#root` 밖으로 옮기지 않는다. 기존의 `.org-preview …` 스타일과
`root.querySelectorAll(...)` 기반 제목·활성 블록·Mermaid 탐색 범위를 유지하기 위해서다.
래퍼와 측정 요소에는 원문 `data-org-id`를 부여하지 않는다.
책자·발표 전용 래퍼 스타일은 `reader.css`에서 한정하고 기존 문서 보기 스타일은 유지한다.

읽기 모드 종료 시 확보한 원래 블록 참조를 같은 순서로 `main`의 직계 자식으로 되돌리고
페이지·측정 래퍼를 제거한다. 대기 중인 새 버전은 §7의 적용 절차로 처리한다.

### 내용별 배치

| 내용 | 페이지 구성 | 한 페이지보다 클 때 |
|---|---|---|
| 제목·문단 | 블록 단위 배치, 제목과 다음 블록을 가능하면 함께 배치 | 해당 블록 전용 페이지와 내부 스크롤 |
| 목록 | 최상위 목록 블록을 유지 | 목록 전용 페이지와 내부 스크롤 |
| 코드 | 코드 블록 전체 유지 | 코드 영역에 가로·세로 스크롤 |
| 표 | 표 전체 유지 | 표 영역에 가로·세로 스크롤 |
| 그림·Mermaid | 이미 로드한 요소를 이동, 비율 유지 | 전용 페이지와 확대·스크롤 |

블록 내용을 자르거나 숨기지 않는다. 넘치는 블록에는 `아래 내용 더 있음` 등의 안내와
키보드로 접근 가능한 스크롤 영역을 제공한다. 발표 중에도 사용자가 스크롤할 수 있다.
스크롤 영역 내부에서는 방향키·PageUp·PageDown을 페이지 넘김으로 가로채지 않는다.

긴 문단의 DOM Range 분할, 목록 항목 분할, 코드 줄 분할, 표 행 분할·머리글 반복은
후속 개선으로 분리한다. 실제 자료에서 내부 스크롤이 자주 필요하다는 결과를 확인한 뒤 도입한다.

### 레이아웃과 지연 로드

`display: none`이나 `hidden` 상태의 페이지 안에서 높이를 측정하지 않는다.
측정이 필요한 블록은 `main.org-preview` 안의 `.reader-measure`로 잠시 이동한다.
측정 영역은 `visibility: hidden`으로 보이지 않게 하되 렌더 트리에는 남기고,
실제 페이지와 같은 본문 폭·폰트·여백 규칙을 적용한다. `aria-hidden`과 `inert`로 읽기와 포커스 대상에서는 제외한다.
높이는 블록의 테두리 상자뿐 아니라 실제 배치에 쓰이는 위아래 여백까지 포함한다.
페이지와 측정 영역은 같은 여백 병합 규칙을 사용해 측정값과 배치 결과가 달라지지 않게 한다.

측정을 위해 이미지나 블록을 복제하지 않는다. 현재 보이는 블록은 가능하면 제자리에서 측정하고,
다른 블록을 측정 영역으로 옮겼다면 동기 측정 구간에서 원래 부모·순서로 복원한 뒤 브라우저에 제어를 돌려준다.
페이지 배치는 계산이 끝난 뒤 적용한다. 숨긴 페이지의 표시 전환과 측정 동작은 별개다.

현재 크기로 페이지를 구성하고, 폰트 준비·이미지 load·Mermaid 렌더 완료로 크기가 바뀌면
읽던 블록을 기준으로 다시 배치한다. 계산 중에는 현재 화면을 유지하고 최신 계산만 반영한다.
실패한 그림이나 다이어그램은 기존 오류 표시와 원문으로 남긴다.

이미지를 모두 미리 다운로드하는 별도 준비 단계나 전역 10초 대기 상한을 두지 않는다.
화면 크기 변경은 짧게 묶어 처리하고, 계산 세대 번호로 오래된 결과의 반영을 막는다.
이미지 실패가 원문 변경에 따른 접근 정보 소실 때문이면 §8의 안내를 적용한다.

## 5. 구현 방식 비교

| 방식 | 장점 | 제약 | 판단 |
|---|---|---|---|
| CSS 다단 배치만 사용 | 초기 구현이 작음 | 표·코드 분할과 원문 위치 연결을 세밀하게 제어하기 어려움 | 보조 수단으로만 사용 |
| 제목마다 한 화면 | 장 이동이 단순함 | 긴 장이 화면을 넘어서 책자처럼 읽기 어려움 | 단독 방식으로 채택하지 않음 |
| 의미 블록을 실제 크기로 측정해 페이지 구성 | 원문과 DOM 요소를 보존하면서 쪽 이동 제공 | 큰 블록은 내부 스크롤 필요 | 첫 구현 권장 |

권장안은 **기존 파서·HTML 렌더러를 유지하고 브라우저에 페이지 구성 계층을 추가**하는 것이다.
화면 크기와 글꼴에 따라 결과가 달라지므로 서버에서 페이지 번호를 미리 결정하지 않는다.
외부 프레젠테이션 프레임워크나 새 프런트엔드 빌드 도구는 도입하지 않는다.
이는 현재 설계 제안이며 구현 방식에 대한 최종 승인은 별도다.

## 6. 현재 코드와 연결 지점

다음은 현재 소스를 읽어 확인한 구조다. 새 보기의 런타임 동작을 검증한 결과는 아니다.

| 파일 | 현재 역할 | 제안하는 변경 |
|---|---|---|
| `internal/orgpreview/server.go` | HTTP·WebSocket, 문서 상태, 인라인 브라우저 화면 | 보기 선택 UI·새 모듈 연결, 인라인 스크립트의 `isCurrent`와 수신·화면 반영 분리 |
| `internal/orgpreview/render.go` | Org·Markdown 공통 HTML 생성 | 기존 출력을 재사용. 필요할 때만 블록 식별 정보 보완 |
| `internal/orgpreview/ir.go` | 문서 노드·ID·원문 바이트 범위 | 기존 탐색 정보 재사용 |
| `internal/orgpreview/protocol.go` | 문서 버전과 탐색 메시지 | 초기에는 기존 계약 유지 |
| `internal/orgpreview/web/mermaid-diagnostics.js` | 주입받은 `isCurrent`로 렌더 결과 유효성 판단 | 첫 구현에서는 모듈 유지. 호출부에서 표시 버전·렌더 세대 기준의 `isCurrent`를 전달하고 렌더 완료 뒤 재배치 |
| `modules/org/23-org-preview.el` | Emacs 버퍼 전송·탐색 | 첫 구현에서는 기존 진입점 유지 |

새 모듈은 다음 책임으로 나눈다. 이름은 제안이다.

- `web/reader-pagination.js`: `main` 직계 자식 블록 참조 보존, 같은 `main` 안의 측정 영역·페이지 래퍼로 이동, 페이지 대응표와 원래 순서 복원.
- `web/reader-view.js`: 보기 전환, 페이지 이동, 목차, 전체 화면, 갱신 대기 상태.
- `web/reader.css`: 책자·발표 배치, 인쇄가 아닌 화면용 스타일, 접근성.

`server.go`에서 기존 방식대로 세 파일을 각각 `go:embed`하고 전용 정적 경로로 제공한다.
`/static/reader-pagination.js`, `/static/reader-view.js`, `/static/reader.css`만 명시적으로 등록하고,
이번 변경에서 범용 `/static/` 파일 서버로 바꾸지 않는다. 기존 인라인 스크립트 전체를 재작성하지 않고 필요한 진입점만 연결한다.
메타데이터 표 처리는 별도 `markdown-frontmatter` 수정에 의존한다. 구현 시 해당 변경을 포함한 기준을 사용해야 한다.

## 7. 상태와 버전의 의미

실제 구현은 기존과 같은 JavaScript를 사용한다. 아래 표기는 설계 설명이며 TypeScript 도입을 뜻하지 않는다.

```text
ReaderState
  mode: document | book | present
  displayedRevision: 현재 DOM을 만든 실시간 버퍼 버전
  latestReceivedRevision: 마지막으로 수신한 실시간 버퍼 버전
  pendingRevision: 아직 화면에 적용하지 않은 최신 메시지, 최대 하나
  displayedDocument: 현재 DOM 요소와 원문 위치 정보
  renderGeneration: 현재 DOM의 렌더 작업 세대
  layoutGeneration: 페이지 재배치 계산 세대
  anchor: 블록 ID + 원문 범위 + 제목 경로 + 앞뒤 블록 문맥
  pageIndex / spread

DisplayedDocument
  sourceKind: live-buffer | linked-file
  sessionID / bufferID / generation: 기존 연결 정보
  documentIR: 응답에 있을 때만 사용
  blocks: 래퍼 생성 전 main.org-preview 직계 자식의 실제 DOM 참조, 원문 순서 유지
  linkedLoadID: 저장된 링크 문서를 다시 불러올 때만 갱신하는 로컬 식별자

Page
  blocks: 해당 쪽으로 이동시킨 DOM 블록 참조
  overflowBlocks: 내부 스크롤이 필요한 블록
```

현재 전역 `revision`의 두 의미를 분리한다. 최신 메시지를 받았다는 이유만으로
표시 중인 DOM의 버전을 올리지 않는다.

| 처리 | 참조하는 상태 | 새 버전이 대기 중일 때 |
|---|---|---|
| 수신 순서와 오래된 메시지 거부 | `latestReceivedRevision` | 최신 하나만 대기 |
| 현재 Mermaid 결과 적용 | `displayedRevision` + `renderGeneration` | 현재 DOM에 대한 작업은 유효 |
| 페이지 크기 계산 | `renderGeneration` + `layoutGeneration` | 현재 DOM 기준으로 계산 |
| Emacs 원문 이동 | 현재 표시 버전과 최신 수신 버전의 일치 확인 | 불일치하면 적용 후 이동 안내 |
| 로컬 링크 열기 | 동일한 일치 확인 후 표시 DOM의 원문 ID | 오래된 ID를 서버 최신 문서에 보내지 않음 |
| Emacs 커서 강조·자동 이동 | 문서 보기일 때만 현재 표시 버전 | 책자·발표에서는 화면과 독서 위치 변경 안 함 |

`renderRevision()`에 해당하는 수신 처리는 수신 상태 갱신과 DOM 반영을 분리한다.
문서 보기에서는 즉시 반영하고, 책자·발표에서는 대기 메시지만 바꾼다.
`ws.onmessage`의 `markFromMessage()` 호출도 같은 정책을 거쳐야 한다.

제안하는 내부 함수:

```text
receiveRevision(message) -> 수신 상태 갱신; 보기별 즉시 반영 또는 대기
applyRevision(message) -> DOM 교체 및 displayedRevision/renderGeneration 갱신
paginate(blocks, layoutOptions) -> PageLayout
findPageForAnchor(layout, anchor) -> pageIndex
setMode(mode) -> 보기 전환 및 필요시 재배치
movePage(direction) -> 페이지 이동
applyPendingRevision() -> 최신 대기 메시지를 반영하고 위치 복원
```

- 현재 블록 ID는 내용과 등장 순서의 영향을 받는다. 영구 ID로 취급하지 않는다.
- 원문 범위는 UTF-8 바이트이며 브라우저 텍스트 위치는 UTF-16이다. 서로 더하지 않는다.
- 첫 구현에서는 블록을 분할하지 않으므로 조각별 DOM ID와 문자 오프셋 계산이 필요하지 않다.
- 후속 세밀한 분할을 도입할 때만 `sourceNodeID`, `sourceRange`, `renderedTextStart/End`, 고유 화면 ID를 추가한다.
- 목차는 원문 블록 목록에서 만들고 화면 배치나 반복 장식에서 다시 수집하지 않는다.
- 저장된 링크 문서는 실시간 `revision`을 흉내 내지 않고 `linkedLoadID`와 `renderGeneration`으로 비동기 작업을 구분한다.
- generation이 바뀌거나 연결이 유효하지 않으면 기존 인증을 우회하지 않는다. 새 미리보기를 열도록 안내한다.

## 8. 표시 유지와 이미지 접근: 검증 결과를 반영한 경량 설계

### 코드와 요청으로 확인한 동작

`commitRevision()`은 이미지 핸들 맵을 교체하지만, **일반 버퍼 수정마다 모든 이미지 URL이 바뀌는 것은 아니다.**
`handleRevision()`은 이전 `browserView`를 재사용하고, 핸들은 `view`와 경로로 계산한다.

| 상황 | 기존 이미지 URL의 실제 요청 결과 |
|---|---|
| 같은 generation에서 같은 이미지가 다음 버전에도 포함 | URL·view 동일, `200` |
| 최신 버전의 등록 핸들에서 이미지가 빠짐 | `400` |
| generation 변경 | 이전 URL `401`, 새 generation URL `200` |
| 경로는 같고 파일 내용만 덮어씀 | `200`이지만 새 파일 바이트 반환 |
| 링크 문서에만 있는 이미지, 원래 버퍼의 다음 버전 수신 | `200`에서 `400`으로 변경 |
| 링크 문서를 다시 조회하여 이미지 핸들 재등록 | 같은 URL로 다시 `200` |

이 결과는 HTTP 핸들러를 실제 호출한 검증이다. 이미 표시한 이미지가 브라우저에서 즉시
사라진다는 뜻은 아니다. 브라우저의 디코딩 상태나 재요청 여부는 별도 관찰이 필요하다.

### 첫 구현 정책

1. 책자·발표 진입 시 현재 `main.org-preview`의 직계 자식 블록을 확보하고, 같은 `main` 안의 페이지 래퍼로 이동한다. 복제하거나 `#root` 밖으로 옮기지 않는다.
2. 이미 로드된 `<img>`와 렌더링된 Mermaid SVG를 그대로 유지한다. `src`를 다시 설정하지 않는다.
3. 페이지 넘김과 재배치는 기존 요소를 이동·표시하는 방식으로 처리한다.
4. 새 문서는 최신 메시지 하나만 대기시킨다. 현재 DOM을 교체하거나 이전 렌더 작업을 취소하지 않는다.
5. 사용자가 `최신 내용 적용`을 눌렀을 때만 새 DOM을 만들고 원문의 대응 위치를 복원한다.
6. 읽기 모드 종료 시 원래 블록 목록의 순서대로 `main`의 직계 자식으로 복원하고 래퍼를 제거한다. 대기 메시지가 있으면 최신 DOM을 반영한다.

별도 일괄 다운로드·Blob 저장소·64 MiB 한도·동시 다운로드 2개·자동 재시작 2회·10초 준비 상한은
첫 구현에서 제거한다. 같은 DOM 요소를 유지하는 것으로 불필요한 재요청을 줄인 뒤,
실제 브라우저에서 재로드로 이미지가 깨지는 경우를 재현했을 때만 좁은 보완을 설계한다.

### 보장하는 것과 보장하지 않는 것

첫 구현은 **새 원문 수신으로 화면과 기존 DOM을 자동 교체하지 않는 것**을 보장 대상으로 한다.
파일 바이트의 완전한 불변 스냅샷이나 모든 브라우저 상황에서의 무재요청을 보장하지 않는다.
아직 로드되지 않은 이미지, 브라우저의 재요청, 원본 이미지 파일 변경, 애니메이션 이미지까지
동결하는 기능은 포함하지 않는다. 재요청이 실패하면 해당 그림에 오류를 표시하고
실시간 문서는 `최신 내용 적용`, 저장된 링크 문서는 `다시 불러오기`를 제공한다.

### 저장된 링크 문서의 별도 문제

저장된 링크 문서를 렌더링할 때 이미지 핸들이 **원래 버퍼의** 맵에 추가된다.
원래 버퍼가 갱신되면 그 맵은 원래 버퍼의 최신 문서에 등장하는 핸들로 대체된다.
따라서 링크 문서에만 있는 이미지의 핸들이 빠질 수 있다. 이번 검증에서는 실제로 `400`을 재현했다.

이것은 책자 보기 때문에 생기는 문제가 아니라 현재 자산 수명 관리의 별도 문제다.
읽기 화면의 전체 이미지 복사로 덮지 않는다. 별도 회귀 테스트와 수정 범위로 관리하며,
수정 전에는 오류 안내와 명시적 다시 불러오기를 제공한다. 원래 링크 자체가 제거되거나
세대가 바뀌어 다시 불러오기 권한도 없으면 원래 문서에서 새 미리보기를 열도록 안내한다.

## 9. 보기 전환과 원문 탐색

- 문서 → 책자: 현재 활성 블록이 포함된 페이지로 이동한다.
- 책자 → 발표: 읽던 블록을 기준으로 발표용 페이지를 다시 계산한다.
- 발표 → 책자: 같은 블록이 포함된 책자 페이지로 돌아온다.
- 읽기 → 문서: 최신 문서를 반영하고 대응하는 블록으로 이동한다.
- 원문 변경 후 블록 ID가 있어도 제목 경로, 해당 블록의 텍스트, 앞뒤 블록 문맥을 함께 비교한다.
  같은 문단이 앞에 추가되면서 ID가 다른 대상을 가리키는 경우를 구분하기 위해서다.
- 문맥상 하나로 대응하는 블록을 찾으면 그 블록이 있는 페이지로 복원한다. 세밀한 조각 위치 복원은 후속 분할 기능과 함께 추가한다.
  대응이 여러 개이거나 확인되지 않으면 해당 장의 시작 또는 문서 시작으로 이동하고 안내한다.
- 페이지 번호는 글자 크기와 보기마다 바뀌므로 영구 위치 식별자로 저장하지 않는다.

책자·발표에서는 Emacs 커서 자동 추적을 끈다. 일반 클릭은 읽기 조작으로 사용한다.
`원문으로 이동`을 명시적으로 실행할 때만 Emacs 탐색 메시지를 보낸다.
표시 버전이 최신 버전과 다르면 오래된 바이트 범위를 보내지 않고 `최신 내용 적용 후 이동`을 안내한다.
로컬 링크의 목적지는 이번 기능에서 바꾸지 않는다. 실시간 버퍼의 로컬 링크는 기존처럼
Emacs에 열기 메시지를 보내며, 표시 버전이 오래됐으면 최신 내용을 적용한 뒤 실행한다.
저장된 링크 문서에서는 기존 브라우저 링크 이동을 유지하고, 새 문서는 문서 보기로 시작한다.
읽기 화면 안에서 별도의 문서 탐색기를 만들지 않는다.

PDF·동영상·외부 문서 iframe을 책자 페이지로 변환하는 기능은 범위 밖이다.
해당 콘텐츠는 기존 미리보기 동작을 사용하며, 프레임 내부 키 입력까지 책자 단축키가
제어한다고 보장하지 않는다. 전체 화면 대상은 책자·발표 화면 자체다.

첫 버전에서는 연결된 세션 안의 읽던 위치를 유지한다. 브라우저를 완전히 닫은 뒤의 위치 복원은 후속 범위다.

## 10. 키보드와 접근성

| 입력 | 동작 |
|---|---|
| `←` / `PageUp` | 이전 페이지 또는 펼침 |
| `→` / `PageDown` | 다음 페이지 또는 펼침 |
| `Home` / `End` | 처음 / 마지막 |
| `Esc` | 첫 Esc는 브라우저가 전체 화면을 해제, 창 상태에서 다시 누른 Esc는 책자로 복귀 |
| 목차 선택 | 해당 제목의 페이지로 이동 |

- 전체 화면 해제는 `keydown` 수신을 전제로 하지 않고 `fullscreenchange`로 추적한다. 이 이벤트만으로 책자 보기까지 연속 전환하지 않는다.
- 입력창·선택 상자·코드 영역·초대형 블록 내부 스크롤에서 입력 중인 키는 가로채지 않는다.
- 단축키는 이 미리보기의 활성 화면에서만 처리한다.
- 페이지 전환 후 버튼 포커스를 유지한다. 스크린리더에는 현재 쪽과 제목을 알린다.
- 화면 밖 페이지는 접근성 트리에서 제외하되 목차 이동은 가능하게 한다. 숨김 상태에서 높이를 읽지 않고 §4의 측정 영역을 사용한다.
- 사용자 동의 없는 자동 넘김·포커스 이동·전체 화면 진입은 하지 않는다.
- 페이지 말림 효과는 넣지 않는다. 모션 감소 설정을 존중한다.

## 11. 구현 순서와 완료 기준

### 단계 1 — 블록 기반 책자 보기

- 원문 순서의 DOM 블록 목록을 유지하고 같은 요소를 페이지 래퍼로 이동.
- 한 쪽·두 쪽 전환, 목차와 쪽 이동, 초대형 블록 내부 스크롤.
- 완료 기준: 문단·표·코드 내부를 분할하지 않아도 내용에 접근할 수 있고, 재배치 후 읽던 블록을 유지한다.

### 단계 2 — 표시 버전과 최신 수신 버전 분리

- 수신 처리와 DOM 반영, Mermaid 현재성 검사, 탐색 메시지 조건을 분리.
- 새 버전은 최신 하나만 대기하고 사용자의 명시적 적용으로 반영.
- 완료 기준: 새 내용 수신으로 현재 DOM·Mermaid 작업·읽던 위치가 바뀌지 않는다.

### 단계 3 — 발표 보기와 전체 화면

- 발표용 배치, 키보드, 전체 화면 진입·이탈.
- 보기 사이 원문 블록 위치 복원.
- 완료 기준: 발표 중 원문 수정·커서 이동으로 페이지가 강제로 바뀌지 않는다.

### 단계 4 — 브라우저 확인과 통합

- 이미지 DOM 이동·재배치의 실제 요청과 표시 상태 확인.
- 기존 문서 미리보기·탐색·Mermaid·링크 동작 회귀 검사.
- 실제 Org·Markdown 문서로 넓은 화면과 좁은 화면 확인.
- 완료 기준: 자동 검사 결과와 실제 브라우저 확인 결과를 함께 남긴다.

### 후속 개선 — 필요성이 확인된 분할만 추가

DOM Range 문단 분할, 목록 항목 분할, 코드 줄 분할, 표 행 분할은 별도 작업이다.
첫 버전의 내부 스크롤 사용 결과를 보고 우선순위를 정한다. 일괄 이미지 Blob 복사도 기본 구현에 포함하지 않는다.

각 단계는 검증 단위다. 갱신 대기가 없는 미완성 책자 보기를 사용자용 완료 기능으로 배포하지 않는다.

## 12. 테스트 계획

| 범위 | 검사할 동작 |
|---|---|
| 페이지 구성 | main 직계 자식 단위·원래 순서·요소 정체성 보존, 목록 내부 보존, 종료 후 래퍼 제거 |
| 측정과 스타일 | 숨긴 페이지의 실측, 페이지와 측정 영역의 폭·여백 일치, 제목 색·문단 간격·root 탐색 유지 |
| 내용 보존 | DOM 이동 전후 텍스트·표·코드 내용 일치, 이미지 요소와 src 유지 |
| 위치 연결 | 한글·이모지, 중복 제목, 앞에 삽입된 동일 문단, 삭제된 블록 |
| 화면 | 목차를 제외한 본문 폭, 한 쪽·두 쪽, 글자 크기 변경, 마지막 홀수 페이지 |
| 비동기 처리 | 느린 이미지·폰트·Mermaid, 현재 DOM의 작업 유지, DOM 교체 후 오래된 결과 폐기 |
| 이미지 수명 | 같은 이미지 URL 유지, 제거·generation 변경, 링크 전용 이미지 핸들 소실, DOM 이동 시 실제 재요청 |
| 발표 | 첫 Esc/둘째 Esc, fullscreenchange, 입력·스크롤 영역 단축키, 커서 이동 무시 |
| 기존 기능 | 문서 실시간 갱신, 원문 탐색, 로컬 링크, 자산 접근 제한 |

- 상태 전환은 Node 테스트, 자산 URL 수명과 정적 자산 제공은 Go 테스트로 확인한다.
- 실제 높이·글꼴·줄바꿈·전체 화면·이미지 재요청은 실제 브라우저에서 확인한다.
  가짜 DOM의 높이값으로 페이지 배치를 판정하지 않는다.
- 현재 preview에는 실제 브라우저 자동화 테스트 환경이 없다. 기존 Mermaid Node 테스트와
  다른 하위 프로젝트의 Vitest/jsdom은 실제 레이아웃 검증을 대신하지 못한다.
- 새 브라우저 자동화 도구를 개발 의존성으로 추가할지, 첫 버전은 재현 절차와 캡처를 남기는
  수동 브라우저 검사로 진행할지 §14에서 결정한다. 어느 쪽이든 실제 브라우저 확인을 생략하지 않는다.
- Emacs 쪽을 변경하게 되면 해당 ERT를 추가한다.

## 13. 위험과 제외 범위

### 주의할 점

- 화면 폭과 글꼴이 달라지면 페이지 수가 바뀐다. 종이책처럼 고정된 페이지 번호를 보장하지 않는다.
- 긴 코드와 복잡한 표는 확대·문서 보기가 필요할 수 있다.
- 원문 변경 후 같은 문장을 항상 정확하게 다시 찾을 수 있다고 보장하지 않는다.
- 같은 이미지 요소를 이동해도 모든 브라우저 상황에서 재요청이 없다고 보장할 수 없다. 실제 요청 횟수와 표시 상태를 확인해야 한다.
- 화면 모형의 예시 페이지 수는 실제 페이지 분할 결과가 아니다.

### 첫 구현에서 하지 않는 것

- PPTX·PDF 파일 내보내기.
- AI 요약 또는 발표 대본 생성.
- 원문과 별개인 슬라이드 편집·드래그 재배치.
- 발표자 전용 창, 원격 리모컨, 녹화, 협업 편집.
- 사용자 정의 페이지 나눔 문법과 장기 독서 위치 동기화.

## 14. 검토 후 확정할 사항

다음은 사용자 요구를 구체화하기 위해 제안한 기본값이며 아직 구현 승인으로 간주하지 않는다.

1. 책자와 발표 모두 변경을 자동 반영하지 않고 `최신 내용 적용`을 사용한다.
2. 가장 상위 제목을 장 경계로 삼고, 나머지 내용은 블록 단위로 실제 높이에 맞춰 쪽에 배치한다.
3. 넓은 화면은 두 쪽, 좁은 화면은 한 쪽을 기본으로 한다.
4. 메타데이터는 `문서 정보`로 접어 두고 발표 본문에서는 제외한다.
5. 처음에는 새 발표 문법을 추가하지 않고 기존 Org·Markdown 문서를 그대로 사용한다.
6. 첫 버전은 블록 단위 배치와 초대형 블록 내부 스크롤로 시작하고 세밀한 분할을 미룬다.
7. 브라우저 자동화 도구를 새 개발 의존성으로 도입할지, 수동 브라우저 검사 절차로 시작할지 결정한다.

## 15. 검증 근거와 현재 상태

사용자 리뷰를 반영해 이미지 접근 전제를 다시 확인했다. 검증 코드는 제품 코드에 추가하지 않고
Go overlay와 별도 Node 탐침으로 실행했다. 상세 명령과 출력은
`../.moai/reports/preview-reader-review/verification.md`에 기록한다.

- Go 실제 핸들러 호출: 유지된 이미지 URL 200, 제거된 핸들 400, 이전 generation 401,
  링크 문서 이미지의 200→400→재조회 후 200을 확인했다.
- 실제 Mermaid 진단 모듈의 비동기 탐침: DOM이 연결된 채 최신 수신 버전만 올리면 기존 작업이
  버려지고, 표시 버전을 분리하면 해당 렌더 작업이 유지되는 것을 확인했다. 실제 브라우저 배치 검사는 아니다.
- generation은 preview 자체 수정 횟수가 아니다. preview는 clipboard 버퍼의 generation을 사용하며,
  소스에서 `set-visited-file-name` 처리 후 증가하는 경로를 확인했다. 전체 Emacs 사용자 동작 재현은 하지 않았다.
- 이전 `design-review.md`의 자산 맵 교체 지적은 일부 조건에는 맞지만, 전체 이미지를 복사해야 한다는
  근거로 일반화하지 않는다. 이전 감사 원문은 보존하고 이 설계와 검증 기록에서 해석을 정정한다.

화면 초안은 `.moai/reports/preview-reader-draft/reader-preview.html`에 있다.
책자·발표 기능은 아직 구현하지 않았다. 현재 문서는 구현 전 설계이며, 새 보기의 테스트 계획을
이미 통과한 결과로 취급하지 않는다. 제품 코드의 링크 이미지 수명 문제도 이번에는 수정하지 않았다.
