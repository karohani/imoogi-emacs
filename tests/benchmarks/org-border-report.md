# Org 하위 영역 테두리 성능 실험

후속 [원인 분리 및 개선 방식 재측정](org-border-methods-report.md)을 함께 참고한다. 아래는 최초 시제품의 역사적 측정값이다.

2026-09-07 측정. **현재 시제품은 대용량 문서에서 유의미한 지연이 발생하므로 기본 활성화하기에 부적합하다.** 테두리가 있는 모든 구현이 느리다는 뜻은 아니다.

## 비교 조건

- macOS / GUI Emacs 31.1, 화면 본문 160열 × 58행. 동봉 패키지와 `modules/14-org.el`만 로드했다. 전체 사용자 설정 비교가 아니다.
- baseline: 기존 제목 색상. cached: 현재 제목부터 해당 하위 영역까지 화면에 보이는 줄에만 테두리를 표시하고 구간 마커를 재사용하는 시제품.
- 전체 문서의 모든 제목에 중첩 상자를 그리는 방식이나 제목 한 줄에만 face `:box`를 적용하는 방식은 측정하지 않았다.
- 1만·10만·100만 줄. many-headings는 제목 1줄 + 본문 9줄 반복, long-subtree는 제목 하나 + 빈 줄 없이 이어지는 긴 본문(명목 줄 수보다 제목 1줄 추가)이다. 후자는 극단 사례다.
- 각 변형마다 새 버퍼를 만들고 baseline→cached / cached→baseline 두 순서를 별도 GUI 프로세스에서 실행했다. 12개 프로세스 모두 정상 종료했다.
- 작업별 준비 5회 + 측정 20회. 입력은 한 번 삽입하고 다음 번 삭제하며 매번 redisplay한다. 이동·스크롤·문서 위치 점프도 측정한다.
- 아래 값은 두 실행의 **중앙값 범위(ms)**. 입력 이벤트 전달·명령 루프·OS 화면 합성 지연은 포함하지 않는다. 낮을수록 빠르다.

## 해석과 구현 판단

표시용 overlay 수는 파일 전체 길이에 비례하지 않았다(최대 10개 또는 51개). 그래도 큰 문서의 편집 지연이 증가했다. 화면 범위 제한과 구간 마커 캐시만으로 성능 문제가 해결되지 않는다.

먼저 수행한 전체 설정 GUI 실험의 스택 샘플에서는 `org-back-to-heading` → `org-element-at-point` → 문서 분석/정규식 탐색이 관찰됐다. 위 격리 측정에서 생긴 모든 지연의 원인까지 확정한 것은 아니다. 문서 분석 캐시를 활성화한 뒤의 편집 비용, 경계 탐색, 화면 갱신을 따로 프로파일링해야 한다.

다음 구현에서는 편집마다 문서 분석을 유발하지 않는 경계 관리, 구조 편집 시에만 캐시 무효화, 짧은 지연 후 갱신 병합, 큰 문서에서 자동 중지를 검토하고 동일 실험으로 다시 검증해야 한다. 현재 모듈에는 테두리를 적용하지 않았다.

접힌 문서, 중첩 제목, 코드 블록·표·이미지, 여러 창, 줄바꿈, refile 등은 아직 검증하지 않았다. 이 파일은 성능 실험이며 완성된 표시 기능이 아니다.

## 재현

사용 중인 Emacs에서 직접 실행하지 않는다. 아래 실행기는 자체 GUI 프로세스만 만들고 각 프로세스에 60초 제한을 둔다. 결과 디렉터리는 실행마다 새 경로를 사용한다.

```sh
python3 tests/benchmarks/run-org-border.py \
  --emacs /Applications/Emacs-31.1.app/Contents/MacOS/Emacs \
  --output /tmp/imoogi-org-border-new-run
```

[원시 측정값](org-border-results.json)에 최초 표시 시간, 입력·이동·스크롤·점프 중앙값/p95/최댓값, GC, overlay 수, 정상 종료 상태를 보관했다. p95는 nearest-rank 방식이며 표본 20개라 변동성 판단에는 제한이 있다.

검증: 두 Elisp 파일 check-parens 통과, Python 구문 검사 통과, 12개 격리 GUI 실행 통과, 임시 native compilation 캐시를 지정한 오프라인 전체 부팅 통과.

## 초기 실험 중 사고

최초 시도는 사용 중인 GUI에서 실행되어 오래 점유했고, 중단 신호를 보내는 과정에서 Emacs가 예상과 달리 종료됐다. 다시 실행하여 `test.org` 버퍼 복원을 확인했다. 저장하지 않은 버퍼 내용의 완전한 복구는 확인할 수 없었다. 최초 시도의 미완료 수치는 결과에서 제외했으며, 이후 실험은 모두 독립 프로세스로 전환했다.
