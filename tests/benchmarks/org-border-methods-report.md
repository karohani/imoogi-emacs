# Org 테두리 재측정과 제안

2026-09-07 후속 실험. **현재 제목 영역의 테두리는 제한 범위 탐색 방식으로 진행할 가치가 있다.** 기존 Org 문서 분석 경로를 매개로 경계를 찾는 시제품은 대용량 편집에서 느렸다. 주변 문자 수를 제한한 시각적 탐색으로 입력 비용을 크게 줄였지만, 완성된 기능이나 무지연 보장은 아니다.

## 원인 분리

5개 변형을 새 버퍼에서 각각 실행했다. baseline은 제목 색상만, cached는 기존 시제품, parser-only는 기존 경계 분석만 하고 테두리를 생략, render-only는 경계 분석 없이 보이는 화면 전체에 세로선을 표시, bounded는 양쪽 20,000글자 이내에서 제목 경계를 찾고 해당 화면 부분만 표시한다. render-only는 같은 의미의 영역을 나타내지 않으므로 비용 분리용 대조군이다.

Org 메뉴를 유지한 첫 묶음은 12개 프로세스 중 10개 완료, 긴 본문 100만 줄의 두 순서는 각각 60초 초과로 중단했다. 스택 샘플에서 `redisplay → AppKit Dock menu → ns_update_menubar → org-context → org-inside-LaTeX-fragment-p → org-element-context`가 관찰됐다. 시간 초과를 테두리 탐색 자체의 실패로 단정하지 않는다.

후속 묶음은 모든 변형에서 Org 로컬 메뉴만 동일하게 제거했다. 나머지 Org 설정과 기존 제목 색상은 유지했다. 12개 프로세스 모두 정상 완료했다. 아래는 이 **메뉴 제외 대조 실험**의 입력 중앙값 범위(ms), 두 비교 순서의 최솟값–최댓값이다.

분석만 하는 대조군도 입력 후 redisplay에서 큰 비용이 발생했다. 따라서 기존 결과를 선 자체를 그리는 비용으로 설명할 수 없다. 제한 범위 방식은 Org 분석 호출을 추가하지 않아 이 실험의 비용을 줄였다. 다른 기능이 이미 문서 분석을 사용하는 실제 사용자 버퍼의 전체 성능까지 개선한다는 의미는 아니다.

## 제안

1. **현재 제목의 영역 하나만, 화면에 보이는 부분에 테두리 표시.** 기존 빨강·파랑·초록·노랑 제목 색상에 맞춰 선 색상을 정한다. 문서 전체의 모든 제목에 중첩 overlay를 만들지 않는다.
2. **탐색에 문자 수 제한.** 양쪽 20,000글자 안에서 경계를 찾고, 제목/끝 경계를 못 찾은 부분은 가로선을 닫지 않는다. 제목 깊이가 확인되지 않으면 중립색을 사용한다. 완전한 Org 의미 분석이 필요한 명령과 장식용 탐색을 분리한다.
3. **이동 중 갱신 병합.** 입력마다 overlay를 다시 만들지 않고, 동일한 표시 영역에서는 재사용한다. 큰 점프·연속 스크롤은 약 100ms 정지 후 갱신하도록 제안한다. 이 지연 갱신은 아직 구현/측정하지 않았다. 제한 탐색에서도 100만 줄 긴 본문 위치 이동 중앙값이 약 31ms여서, 현재 수치만으로 즉시 갱신이 항상 매끄럽다고 말할 수 없다.
4. **예산 초과 시 표시 생략.** 한 번의 탐색/그리기에서 문자 수 외에도 줄·overlay 수 상한을 적용하고, 예산 초과나 미지원 구조에서는 기존 제목 색상만 남긴다. 전체 Org 캐시나 메뉴 기능을 사용자 설정에서 일괄 해제하는 것은 이번 제안이 아니다.

구현 후 수용 기준 제안: 100만 줄에서 테두리의 추가 입력 비용 p95 ≤5ms, 스크롤 추가 비용 p95 ≤8ms, 제목 전환·접기·refile 후 잘못된 테두리 없음. 현재 표는 중앙값이며 이 수용 기준의 통과 판정이 아니다.

## 남은 검증

시제품은 단순 제목 문법을 이용한다. inlinetask, 코드 블록/서랍, 빈 제목·탭, 접힌 영역, 줄바꿈, 매우 긴 단일 행, 여러 창, narrowing, 구조 변경과 undo/refile을 실사용 수준으로 검증하지 않았다. 현재 선 색상도 비교용 고정 색상이다. marker 캐시를 쓰는 이전 변형에는 자식 제목으로 진입할 때의 무효화가 부족하다. 단순 regexp 탐색을 일반 Org 파서로 사용하면 안 된다.

자동 검증은 중첩/형제 제목 경계, 제목 삽입 후 재계산, 탐색 범위 밖 미확인 경계 열기 3개가 통과했다. 성능 계측 코드는 `tests/benchmarks/`에만 있으며 실사용 모듈에 테두리나 메뉴 변경을 설치하지 않았다.

## 재현과 증거

```sh
python3 tests/benchmarks/run-org-border.py \
  --emacs /Applications/Emacs-31.1.app/Contents/MacOS/Emacs \
  --output /tmp/imoogi-border-new-comparison --without-org-menu
```

`--without-org-menu`를 생략하면 메뉴 포함 비교다. 새 결과 디렉터리를 요구하며, 격리 프로세스별 60초 제한이 있다. [원시 결과](org-border-methods-results.json)에는 메뉴 포함 시간 초과와 완료된 부분 결과도 상태와 함께 보존했다. 미완료 결과는 위 표에 사용하지 않았다.
